# My Tasks

빌드 도구 없이 HTML·CSS·JavaScript만으로 만든 할 일 관리 앱입니다.
데이터는 브라우저의 `localStorage`에 저장되며 서버가 필요 없습니다.

## 실행

```bash
git clone https://github.com/muanyangpa/my-tasks.git
cd my-tasks
open index.html
```

의존성도 빌드 과정도 없습니다. `index.html`을 브라우저로 열면 바로 동작합니다.

## 기능

**할 일 관리**
- 추가 / 삭제 / 완료 토글
- 텍스트를 더블클릭해 그 자리에서 수정 (Enter 저장, Esc 취소)
- 업무 · 개인 · 공부 세 가지 카테고리와 색상 태그
- 키워드 기반 자동 카테고리 분류 (드롭다운의 "자동", 기본값)
- 카테고리 필터, 실시간 검색 (일치 부분 강조)
- "2시간 전" 형식의 생성 시간 표시

**진행률 대시보드**
- 전체 진행률과 프로그레스 바
- 카테고리별 완료 비율
- 오늘 추가한 할 일 개수

**그 외**
- 다크 / 라이트 모드 (선택 값 저장)
- 정렬: 직접 정렬 · 생성일순 · 카테고리순 · 완료 상태순
- 드래그 앤 드롭으로 순서 변경
- JSON 내보내기 / 가져오기 (가져오기 전 백업 선택 가능)
- 완료된 항목 일괄 삭제

**키보드 단축키**

| 키 | 동작 |
|---|---|
| `Alt` + `N` | 입력창으로 이동 |
| `Alt` + `1` ~ `4` | 전체 / 업무 / 개인 / 공부 필터 |
| `Enter` | 할 일 추가, 편집 중 저장 |
| `Esc` | 편집 취소, 다이얼로그 닫기 |

## 파일 구성

```
index.html    화면 구조
style.css     테마 토큰과 스타일
script.js     상태 관리, 렌더링, 이벤트
docs/         기능별 설계 문서
web_version/  데스크톱 전체 화면 레이아웃 (별도 버전)
```

좁은 화면 기준으로 만든 루트 버전과, 데스크톱 2단 레이아웃인
[`web_version/`](web_version/)이 각각 독립적으로 동작합니다.

## 구현 노트

만들면서 판단이 필요했던 부분들입니다.

### 정렬 기준과 드래그 정렬의 충돌

"생성일순 정렬"과 "드래그로 직접 정렬"은 동시에 성립할 수 없습니다. 생성일순이 켜진 상태에서 항목을 끌어다 놓아도, 다시 그리는 순간 원래 자리로 돌아갑니다.

정렬 기준은 화면에만 적용하고, 배열 순서 자체를 직접 정렬로 삼았습니다. 드래그를 시작하면 `freezeSortOrder()`가 지금 보이는 순서를 배열에 굳히고 기준을 "직접 정렬"로 전환합니다. 이때 다시 그리지 않는 것이 중요합니다 — 렌더링하면 끌고 있던 요소가 사라져 드래그가 끊깁니다.

필터나 검색으로 일부만 보이는 상태의 드래그도 처리했습니다. 보이는 항목들이 차지하던 배열 위치는 그대로 두고 그 자리에만 새 순서를 채웁니다. 가려진 항목이 밀려나지 않습니다.

### 자동 분류가 사용자의 선택을 이기지 않는 방법

할 일을 입력하면 키워드를 보고 카테고리를 추측합니다. 문제는 "자동으로 정한 값"과 "사용자가 고른 값"이 충돌할 때입니다. 입력할 때마다 드롭다운이 저절로 바뀌게 하면, 사용자가 방금 고른 카테고리를 코드가 덮어쓰게 됩니다.

드롭다운에 `자동` 항목을 넣고 기본값으로 두었습니다. `자동`일 때만 키워드로 판단하고, 사용자가 업무·개인·공부를 고르면 그 선택은 어떤 경우에도 건드리지 않습니다. 자동이 언제 작동하는지가 화면에 그대로 드러납니다.

`'auto'`는 저장되지 않습니다. 드롭다운의 UI 상태일 뿐이고, 추가하는 순간 실제 카테고리로 확정됩니다. 덕분에 기존 데이터, 내보내기 파일, 필터, 통계를 하나도 고치지 않았습니다. 인라인 수정의 카테고리 선택에는 `자동`이 없습니다 — 이미 있는 할 일의 분류를 고치는 자리이므로 자동이 끼어들 이유가 없습니다.

판단은 카테고리별로 일치한 키워드 **개수**로 합니다. 동점이면 업무 > 개인 > 공부 순서입니다. 하나도 못 찾으면 기본값을 쓰되 힌트에 `키워드 없음 · 기본값 업무`라고 적습니다. 맞춘 척하지 않는 편이 낫습니다.

키워드 길이에 가중치를 주는 방식도 검토했지만 뺐습니다. 정확도는 조금 오르는데 왜 그렇게 분류됐는지 예측할 수 없게 됩니다.

### 프로그레스 바를 다시 만들지 않는 이유

CSS `transition: width`는 같은 요소의 값이 바뀔 때만 동작합니다. 대시보드를 JavaScript로 매번 새로 만들면 항상 새 요소라 전환 효과가 보이지 않습니다. 그래서 대시보드 마크업은 `index.html`에 고정해 두고 텍스트와 `style.width`만 갱신합니다.

### 편집 중인 입력값을 상태로 들고 있는 이유

다른 항목을 체크하거나 필터를 바꾸면 목록이 다시 그려집니다. 입력값이 DOM에만 있으면 그 순간 타이핑하던 내용이 사라집니다. `editingDraft`에 담아 두고 렌더링 후 복원하며 커서를 끝으로 되돌립니다.

### macOS에서는 `e.key`로 단축키를 만들 수 없다

macOS에서 Option + N은 죽은 키(`˜`)라 `e.key`가 `'n'`이 아닙니다. Option + 1도 `'¡'`이 됩니다. 물리 키 위치인 `e.code`(`KeyN`, `Digit1`)를 쓰지 않으면 맥에서 단축키가 전혀 동작하지 않습니다.

### 테마를 `<head>`에서 먼저 적용하는 이유

`script.js`는 `</body>` 앞에서 실행되므로, 거기서 테마를 적용하면 다크 모드 사용자에게 흰 화면이 한 번 번쩍입니다. 첫 페인트 전에 `data-theme`을 설정합니다. 저장된 값이 없으면 시스템 설정을 따르되 저장하지는 않습니다 — 사용자가 직접 토글해야 명시적 선택으로 기록됩니다.

### 100개 이상에서의 렌더링

- 항목을 `DocumentFragment`에 모아 `replaceChildren`으로 한 번에 교체
- 통계는 카테고리별로 여러 번 순회하지 않고 한 번의 루프로 계산
- 고정된 DOM 참조는 렌더링마다 다시 찾지 않고 캐싱
- 검색 입력은 120ms 디바운스

가상 스크롤은 넣지 않았습니다. 수백 개 수준에서는 위 네 가지로 충분하고 복잡도가 크게 올라갑니다.

### 입력값을 그대로 다루기

할 일 내용은 `textContent`로만 넣습니다. 검색어 강조도 `innerHTML` 대신 텍스트 노드와 `<mark>` 요소를 직접 조립합니다. `<script>` 같은 내용을 입력해도 글자 그대로 표시됩니다.

### 확인 창

네이티브 `confirm()` 대신 `<dialog>`를 씁니다. `confirm()`은 다크 모드에서 스타일이 적용되지 않고 브라우저 UI가 그대로 뜹니다. `<dialog>`는 Esc 취소가 기본 동작이고 `::backdrop`까지 테마를 따릅니다.

## 데이터

`localStorage`에 다음 키로 저장됩니다.

| 키 | 내용 |
|---|---|
| `my-tasks` | 할 일 목록 |
| `my-tasks-theme` | 선택한 테마 |
| `my-tasks-sort` | 선택한 정렬 기준 |

할 일 하나의 구조입니다.

```js
{
  id: 1727000000000,        // 고유 식별자
  text: "장보기",
  done: false,
  category: "personal",     // work | personal | study
  createdAt: 1727000000000
}
```

내보내기 파일은 이 배열을 `todos` 필드에 담습니다. 가져오기는 내보내기 형식과 할 일 배열만 있는 형식을 모두 받으며, 형식이 맞지 않는 항목은 건너뛰고 중복된 `id`는 분리합니다.

## 알려진 제약

- 드래그 앤 드롭은 HTML5 Drag and Drop API를 쓰므로 **터치 기기에서는 동작하지 않습니다.**
- 데이터가 브라우저에 저장되므로 기기 간 동기화가 되지 않습니다. 브라우저 데이터를 지우면 함께 사라집니다.
- 시크릿 모드 등 저장이 막힌 환경에서는 새로고침 시 데이터가 유지되지 않습니다.

## 만든 과정

다섯 단계로 나누어 만들었습니다.

1. 기본 구조 — 추가 / 삭제 / 완료 토글, `localStorage` 저장
2. 카테고리 — 드롭다운, 색상 태그, 필터, 생성 시간
3. 진행률 대시보드 — 통계, 인라인 수정, 애니메이션
4. 다크 모드 — 테마 토글, 검색, 일괄 삭제, 단축키
5. 마무리 — 내보내기 / 가져오기, 정렬, 드래그 정렬, 성능 개선

# 키워드 기반 자동 카테고리 분류 — 설계

날짜: 2026-09-29
대상: My Tasks (index.html / style.css / script.js)

## 목표

할 일을 입력하면 내용의 키워드를 보고 업무·개인·공부 중 하나를 자동으로 고른다.
사용자가 직접 고른 카테고리는 어떤 경우에도 덮어쓰지 않는다.

## 결정 사항

### 1. "자동"은 드롭다운 옵션이다

카테고리 드롭다운에 `자동` 항목을 추가하고 기본값으로 둔다.
`자동`일 때만 키워드로 판단하며, 사용자가 업무/개인/공부를 고르면 그 선택을 절대 건드리지 않는다.

대안으로 "입력할 때마다 드롭다운이 저절로 바뀌는" 방식을 검토했으나 제외했다.
사용자의 선택이 제멋대로 바뀌는 것처럼 보이고, 언제 자동이 멈추는지 설명하기 어렵다.

### 2. `'auto'`는 저장하지 않는다

`todo.category`에는 지금처럼 `work | personal | study`만 들어간다.
`'auto'`는 드롭다운의 UI 상태일 뿐이고, 추가하는 순간 실제 카테고리로 확정된다.

이 결정 덕분에 기존 데이터, 내보내기 파일, 필터, 통계, 마이그레이션 로직을
하나도 수정하지 않는다. 자동 분류는 카테고리를 정하는 또 하나의 입력 방법일 뿐,
데이터 모델에는 존재하지 않는다.

### 3. 판단은 일치한 키워드 개수로

- 입력을 소문자로 바꿔 부분 문자열로 대조한다 ("팀 회의 준비" ⊃ "회의")
- 카테고리별로 일치한 키워드 **개수**가 점수
- 동점이면 업무 > 개인 > 공부 (기존 `CATEGORY_ORDER` 순서)
- 0점이면 기본값 `work`, 단 점수 0을 호출부에 그대로 알려 "추측 못 함"을 구분한다

키워드 길이에 가중치를 주는 방식도 검토했으나 제외했다. 정확도는 조금 오르지만
왜 그렇게 분류됐는지 사용자가 예측할 수 없다.

### 4. 키워드는 내장 고정 목록

`script.js` 상단 상수. 편집 UI는 만들지 않는다.
같은 단어가 두 카테고리에 겹치면 양쪽 점수가 같이 올라 판단에 기여하지 못하므로,
카테고리 간 중복과 카테고리 내 부분 문자열 쌍(예: `보고` / `보고서`)을 금지한다.
이 제약은 테스트로 강제한다.

## 인터페이스

```js
classify(text) → { category, score, matched }
```

순수 함수. DOM과 상태를 건드리지 않아 Node에서 그대로 테스트할 수 있다.

- `category` — 판단 결과 (`work | personal | study`)
- `score` — 일치한 키워드 수. 0이면 추측하지 못한 것
- `matched` — 일치한 키워드 목록. 화면 힌트에 근거로 표시한다

## 화면

```
[ 회의 자료 정리_          ] [ 자동 ▾ ] [ 추가 ]
  업무로 분류 · 회의, 자료
```

- 힌트는 입력창 아래 한 줄
- 키워드를 못 찾으면 `키워드 없음 · 기본값 업무`로 표시한다. 맞춘 척하지 않는다
- 사용자가 직접 카테고리를 고르면 힌트를 숨긴다
- 입력이 비면 힌트를 숨긴다
- 추가한 뒤에도 드롭다운은 `자동`에 남는다

## 범위 밖

- **인라인 수정의 카테고리 select에 `자동`을 넣지 않는다.**
  이미 있는 할 일의 분류를 고치는 자리인데 자동이 끼어들면 목적과 어긋난다.
  `createCategorySelect()`가 `CATEGORIES`를 순회하므로 자동으로 제외된다.
- **기존 할 일을 소급 분류하지 않는다.** 사용자가 정한 분류를 코드가 덮어쓰지 않는다.
- 키워드 편집 UI, 학습 기능.

## 테스트

`classify`가 순수 함수이므로 Node에서 검증한다.

- 단일 매치 / 복수 매치로 점수가 높은 쪽 선택
- 동점 시 업무 > 개인 > 공부
- 무매치 시 `score === 0` 이고 카테고리는 기본값
- 대소문자 무시, 빈 문자열
- 키워드 목록 제약: 카테고리 간 중복 없음, 카테고리 내 부분 문자열 쌍 없음
